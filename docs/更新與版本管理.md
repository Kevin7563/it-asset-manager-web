# 更新與版本管理（Web 版）

本專案的版本以 `package.json` 的 `version` 為唯一來源，Git 標籤格式 `vX.Y.Z`，
GitHub Actions 會在推送標籤時自動打包並建立 Release；Web 版的「🔄 線上更新」就是讀這個 Release。

## 一、發行流程（維護者）

```powershell
cd d:\it-asset-manager-web

# 1) 改版（會自動建立 vX.Y.Z 標籤）
npm run release:patch     # 1.0.0 → 1.0.1（修 bug）
npm run release:minor     # 1.0.x → 1.1.0（新功能）
npm run release:major     # 1.x.x → 2.0.0（不相容變更）

# 腳本會自動：commit → push 分支 → push 標籤
```

推送標籤後（`npm run release:*` 會自動完成）：

1. 本機打包 `out/it-asset-manager-web-vX.Y.Z.zip`（只含程式檔：`server.js`、`lib/`、`public/`、`package.json`、`README.md`、`CHANGELOG.md`、`docs/`、`scripts/`）
2. 用 `gh release create` 建立 GitHub Release 並附上該 ZIP
3. Web 版「檢查更新」即可看到新版本

> 若想在本機先打包檢查：`npm run release:pack` → `out/it-asset-manager-web-vX.Y.Z.zip`

### 選用：改用 GitHub Actions 自動發行

目前 `gh` token 沒有 `workflow` scope，因此 Actions 定義先放在 `docs/ci/release-workflow.yml.txt`。要啟用：

```powershell
gh auth refresh -s workflow
mkdir .github\workflows -Force
copy docs\ci\release-workflow.yml.txt .github\workflows\release.yml
git add .github && git commit -m "ci: enable release workflow" && git push
```

之後只要推送 `v*` 標籤，Actions 就會自動打包並建立 Release（`release.mjs` 的 gh 步驟會因 Release 已存在而略過）。

## 二、在 Web 版執行更新

1. 以「全功能」權限登入 → 「📥 匯入／備份」→ **ℹ️ 版本與系統資訊**
2. **🔄 檢查更新** → 顯示目前／最新版本、發佈日期、更新內容
3. **⬇️ 下載更新檔** → 下載 Release 的 ZIP 並解壓到 `updates\staged`
4. **✅ 套用並重新啟動**
   - 先把目前程式檔備份到 `data\backups\app_before_update_<舊版>_<時間>.zip`
   - 覆蓋 `server.js`、`lib/`、`public/`、`package.json` 等程式檔
   - 啟動 `scripts/update-restart.mjs`：等舊進程結束後用同一個 Node 重新啟動
   - 頁面會輪詢 `/api/health`，服務回來後自動重新載入

**不會被更動**：`data\`（資料庫、附件、imported_files、backups）、`config.json`、`node_modules`、Git 歷史。

## 三、回復舊版

- 程式檔備份：`data\backups\app_before_update_*.zip`（解壓覆蓋即可）
- 或使用 Git：`git checkout v1.0.0`

## 四、API（管理者，需「全功能」權限）

| 方法 | 路徑 | 說明 |
| --- | --- | --- |
| GET | `/api/update/check` | 檢查最新版本（5 分鐘快取） |
| POST | `/api/update/download` | 下載 Release ZIP 並解壓到 `updates\staged` |
| POST | `/api/update/apply` | 套用（需 `{ "confirm": "UPDATE" }`） |
| POST | `/api/update/restart` | 重新啟動服務 |

## 五、私有倉庫 / 自架更新來源

- 私有倉庫：`config.json` 設 `githubToken`（或環境變數 `WEB_UPDATE_TOKEN`），需 `repo` 讀取權限
- 自架：`config.json` 設 `updateUrl` 指向一個 JSON（格式同 GitHub release，或簡化版）：

```json
{
  "version": "1.0.2",
  "notes": "修正 XXX",
  "publishedAt": "2026-11-11",
  "downloadUrl": "https://your-server/it-asset-manager-web-v1.0.2.zip",
  "fileName": "it-asset-manager-web-v1.0.2.zip",
  "size": 123456
}
```

- 離線／內網：直接把 `updateUrl` 指向內部網址的 JSON 即可（ZIP 也放在內網）

## 六、版本規則建議

| 類型 | 版本 | 例子 |
| --- | --- | --- |
| 修 bug、調整文字 | patch | 1.0.1 |
| 新增頁面／功能 | minor | 1.1.0 |
| 資料庫結構或 API 不相容 | major | 2.0.0 |

> 更新只覆蓋程式檔；若新版本需要資料庫結構變更，`service.ensureSchema()` 會在啟動時自動補欄位。
