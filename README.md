# IT 資產管理系統｜Web 版

多部門共用的 Web 版資產管理系統（Node.js + SQLite + 原生前端），與單機版（Electron）為**各自獨立的專案**：

| | 專案 |
| --- | --- |
| 🖥️ 單機版 | [it-asset-manager](https://github.com/Kevin7563/it-asset-manager)（Electron，分支 `desktop`） |
| 🌐 Web 版 | **本專案** |

## ✨ 功能

- 📊 總覽看板（統計卡、搜尋、Excel 盤點總表匯出）
- 📦 資產管理（新增／編輯／報廢／回收桶〔🔄 還原、🗑️ 永久刪除、🧹 全部清空〕／維修／轉移、履歷彈窗與匯出）
- 🔍 可輸入關鍵字的選擇器：**維修／轉移的資產**、**廠商資料維護／新增維護紀錄的廠商**、**維護歷程看板（搜尋紀錄＋匯出廠商同一欄位）**，以及**資源回收桶搜尋**（支援 `↑` `↓` `Enter`、多關鍵字以空格分隔）
- 🏢 廠商管理（看板／維護／維護歷程／附件 NDA 與合約、廠商與維護歷程匯出）
- 🧩 欄位管理、👥 帳號管理（勾選式權限）、🔒 修改密碼
- 📥 匯入／備份（Excel 匯入、資料庫備份／還原、匯入單機版備份、附件路徑修復、附件 ZIP）
- 🔄 **版本與更新**（獨立頁面：系統版本資訊、GitHub Releases 檢查更新／下載／套用並自動重啟）
- ✏️ 多人同時編輯鎖定（10 分鐘 TTL）＋登入 Session 持久化（重啟不掉登入）
- 🔄 **線上更新**：從 GitHub Releases 檢查／下載／套用更新並自動重啟
- 🖥️ **背景執行＋系統匣常駐**：雙擊 `start.bat` 先顯示啟動說明，之後服務在**背景**執行（不再有黑色命令視窗），右下角常駐圖示可按右鍵「重新啟動服務／停止服務」
- 📌 **桌面執行圖示**：安裝（或第一次啟動）時自動在桌面建立捷徑，也可隨時執行 `install.bat` 重建

## 🚀 快速開始

### 方式 A：可攜版（免安裝 Node.js）⭐ 新電腦最省事

1. 下載 `it-asset-manager-web-portable-vX.Y.Z.zip`（約 44 MB，已內含 Node.js 與相依套件）
2. 解壓縮到固定資料夾（例如 `D:\IT資產管理系統`）
3. 雙擊 **`start.bat`** → 先顯示啟動說明視窗 → 按「啟動服務」
   - 服務在**背景**執行（不會有黑色命令視窗），右下角通知區域出現**常駐圖示**
   - 自動開啟瀏覽器 <http://localhost:3010>
4. 右下角圖示按**右鍵**：開啟網頁／啟動服務／**重新啟動服務**／**停止服務**／結束常駐程式

- 不需要安裝 Node.js、不需要 `npm install`、不需要網路
- 第一次啟動會自動建立 `data\asset_data.db`（預設 `admin` / `5508888`、`User` / `1234`）與**桌面執行圖示**
- 想重建桌面／開始功能表捷徑：雙擊 **`install.bat`**
- 詳細說明見解壓後的 **`安裝與啟動.txt`**

### 方式 B：程式檔 + 自行安裝 Node.js

1. **安裝 Node.js LTS**（20 或 22 以上）：https://nodejs.org/
2. **取得程式**：到 [Releases](https://github.com/Kevin7563/it-asset-manager-web/releases) 下載 `it-asset-manager-web-vX.Y.Z.zip`，解壓到固定資料夾（例如 `D:\it-asset-manager-web`）
3. **雙擊 `start.bat`**：第一次會自動 `npm install`（有進度視窗），完成後在**背景**啟動並開啟 http://localhost:3010
   - 右下角常駐圖示可右鍵「重新啟動服務／停止服務」；第一次啟動同時建立桌面執行圖示

> 完整圖文步驟（含區網連線、防火牆、開機自動啟動、常見問題）請看 **[docs\安裝與啟動.md](docs/安裝與啟動.md)**

### 手動啟動（開發／除錯用，會顯示主控台）

```powershell
cd d:\it-asset-manager-web
npm install
npm start          # 也可以 npm run web（舊習慣相容）
```

- 日常使用建議直接雙擊 `start.bat`（背景執行＋系統匣常駐）
- `start.bat` 支援參數：`--no-browser`（不自動開瀏覽器）、`--silent`（略過啟動說明視窗）

- 預設帳號：`admin` / `5508888`（全功能）、`User` / `1234`（一般查詢與報表匯出）
- 🔒 第一次登入後請立刻更換 `admin` 密碼
- 第一次啟動若找不到資料庫，會**自動建立** `data\asset_data.db` 並寫入預設帳號與欄位選項
- 區網其他電腦／手機：`http://<伺服器IP>:3010`（記得在 Windows 防火牆允許 Node.js）

## ⚙️ 設定

優先順序：**環境變數 > `config.json` > 預設值**

| 設定 | 環境變數 | config.json | 預設 |
| --- | --- | --- | --- |
| 連接埠 | `WEB_PORT` | `port` | `3010` |
| 綁定位址 | `WEB_HOST` | `host` | `0.0.0.0` |
| 資料庫 | `WEB_DB` | `dbPath` | `data\asset_data.db` |
| 更新倉庫 | `WEB_UPDATE_REPO` | `githubRepo` | `Kevin7563/it-asset-manager-web` |
| 自訂更新來源 | `WEB_UPDATE_URL` | `updateUrl` | GitHub Releases API |
| 私有倉庫 Token | `WEB_UPDATE_TOKEN` | `githubToken` | 空 |

```powershell
copy config.json.example config.json
npm start
```

## 📁 資料存放

```
data\asset_data.db                資料庫（WAL）
data\vendor_files\{nda,contract,maint}\<id>\   附件
data\imported_files\              匯入的單機版自訂資料夾附件
data\backups\                     資料庫／程式檔備份
updates\                          線上更新下載與暫存
```

> 搬家時只要複製整個 `data\` 資料夾即可。

### 資產編號規則

```
類別-部門-YYYYMMDD-流水號        例：HW-IT-20100423-0001
              └─ 採購/購買日期（未填時才用建檔日）
```

- 跨部門轉移會重新編號，但**日期仍沿用原採購日期**
- 既有資料若編號日期是建檔日（例如全部都是匯入當天），可用「📥 匯入／備份 → 🧰 資料修復」重新編號

### 📦 資料表匯入／匯出（Excel）

「📥 匯入／備份」頁上方兩個區塊：

| 區塊 | 功能 |
| --- | --- |
| 📦 資產資料表匯入／匯出 | 📂 匯入（新增／更新）、📤 匯出資產資料、⬇️ 空白範本 |
| 🏢 廠商資料表匯入／匯出 | 📂 匯入（新增／更新）、📤 匯出廠商資料、⬇️ 空白範本 |

**匯出檔可直接修改後整批重新匯入**（欄位與匯入完全相同，第 3 列為欄位、第 4 列起為資料）：

1. 按 **📤 匯出資產資料** → 開啟 Excel 修改名稱／保管人／規格…等
2. 回系統按 **📂 匯入（新增／更新）** 選同一個檔案

匯入規則：

| 情況 | 結果 |
| --- | --- |
| 有「資產編號」且存在 | **更新**該筆（編號不變） |
| 沒有編號、但「原廠序列號」已存在 | **更新**該筆 |
| 都沒有 | **新增**（依採購日期自動編號） |

- 更新時以檔案內容為準（留空＝清空該欄）
- 變更「資產大類」或「所屬部門」會重新產生資產編號（同步維修／履歷／轉移紀錄）
- 廠商以「廠商公司名稱」為鍵：不存在＝新增、已存在＝更新（空白欄位不會清掉原值）

### 🧰 資料修復（一次性）

「📥 匯入／備份 → 🧰 資料修復」可修正舊版匯入造成的問題：

| 選項 | 作用 |
| --- | --- |
| 重新產生資產編號（依採購日期） | 依 `類別-部門-採購日期-流水號` 重編，並同步維修／履歷／轉移紀錄的編號 |
| 清除重複的維運備註 | `維運備註說明` 與 `資產規格/備註` 相同時，清空維運備註 |

- 先按「🔍 預覽」看筆數與編號變更範例，再按「✅ 執行修復」
- 執行前自動備份到 `data\backups\repair_before_*.db`；可重複執行（已正確的不會再變）
- 命令列：`npm run repair:data -- --db data\asset_data.db --dry-run`

## 🔄 線上更新與版本管理

1. 「系統管理 → 🔄 版本與更新」→ **🔄 檢查更新**
2. 有新版本時：**⬇️ 下載更新檔** → **✅ 套用並重新啟動**
3. 套用前會自動把目前程式檔備份到 `data\backups\app_before_update_*.zip`；資料庫、附件、`config.json` 不會被更動

發行新版本（維護者）：

```powershell
npm run release:patch     # 或 release:minor / release:major
```

腳本會自動：commit → push 分支與 `vX.Y.Z` 標籤 → 打包 `out\it-asset-manager-web-vX.Y.Z.zip` → 用 gh CLI 建立 GitHub Release（附上 ZIP）。
Web 版的「🔄 檢查更新」就是讀這個 Release（詳見 `docs\更新與版本管理.md`）。

## 🧩 權限

| 權限 | 說明 |
| --- | --- |
| 👑 全功能 | 所有功能（系統管理員） |
| 📊 一般查詢與報表匯出 | 總覽查詢、Excel 報表 |
| 🏢 廠商管理 | 廠商資料、維護歷程、附件 |
| 📦 資產管理 | 資產、維修、轉移、回收桶（還原／永久刪除單筆） |

> 🧹「清空回收桶（全部永久刪除）」屬高風險操作，僅限 **👑 全功能** 帳號。

## 📜 使用日誌（稽核）

「系統管理 → 📜 使用日誌」（僅「全功能」權限）

- 自動記錄：登入／登出／**登入失敗**、資產與廠商異動、維修／轉移、匯入匯出、備份還原、帳號權限變更、系統更新等操作
- 每筆含：**時間、帳號、顯示名稱、權限、動作、對象、對象編號、內容、IP**
- 可依 **日期區間／帳號／動作／關鍵字** 篩選並分頁
- **📥 匯出報表（Excel）**：依目前篩選條件匯出，供稽核備查

> 日誌存於同一資料庫（`activity_logs` 資料表），會隨 `data\` 備份一起保留。

## 📄 分頁（所有看板）

所有清單／看板都支援分頁，**每頁可選 10 / 30 / 50 / 100 筆**（預設 30）：

- 總覽看板、維修履歷、轉移履歷、廠商管理看板、廠商維護歷程、資源回收桶、帳號清單、使用日誌
- 分頁列顯示「第 A–B 筆 / 共 N 筆」與「第 X / Y 頁」，提供 `«` 第一頁、上一頁、下一頁、`»` 最後頁
- 搜尋／篩選條件變更時自動回到第 1 頁；上方統計卡仍以全部資料計算
- 使用日誌為伺服器端分頁（只取當頁資料），資料量大也不影響速度
